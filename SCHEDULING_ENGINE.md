# Scheduling and routine editor

AI proposes learning topics or allocation preferences. TypeScript deterministic code (`src/lib/routine/engine.ts`) schedules in 15-minute increments, with one allocation per subject per pass before extra frequencies. Mandatory subjects precede optional ones; priority breaks ties. Day scoring discourages same-subject clumping and favors lighter days. Prerequisites must be completed or receive enough earlier scheduled minutes. No infeasible result is labelled valid.

The validator returns structured hard errors (coverage, time windows, capacity, overlap, prerequisites, daily subject count, locks, invalid fields) and soft long-session warnings. Rest days have zero capacity. Topic objectives remain in the library when a draft session is removed. Current generation plans one seven-day window, not an entire multi-month timetable; weekly targets/preferences carry forward. Remaining objective time and earlier unfinished daily tasks remain visible rather than being silently discarded.

The editor at `/planner/customize` contains subject targets/library, week/day/agenda calendar and a session inspector. Desktop HTML drag/drop moves sessions or places topics in time slots. Form controls provide keyboard/touch move/resize alternatives. It includes fixed commitments, explicit locking/unlocking, bounded undo/redo, debounced draft saves, version conflicts, local recovery, saved version preview, deterministic regeneration and optional AI allocation proposals with before/after minutes. A proposal modifies only a draft after the user applies it. Changing mandatory targets is a deliberate user action.

Approval is explicit and transactional. Server SQL repeats critical constraints, checks existing planner capacity/overlap and rejects stale versions. A saved draft does not replace its approved snapshot. Re-activation can update eligible future pending sessions, preserves notes and completed/running work, and refuses removal of unfinished activated tasks. Users must explicitly resolve those tasks. Approval creates the selected week's planner tasks; per-subject topic notes and completion are available in the daily planner.

Current limits: no pointer-drag resize handle (use duration controls), no OR-Tools solver, no automatic multi-week deadline optimization, no automatic import of external calendars. AI optimization edits allocation targets, not arbitrary time-window intent. These remain explicit refinements rather than simulated features.

Individual daily overrides are distinct from generated routine replacement. A server trigger enforces current explicit locks even on direct task APIs. Unlocked date/assignment overrides become unslotted work with the historical routine link retained, so overdue work can move beyond an old week. Creating/attaching routine tasks still requires approved activation; notes and completion do not require regenerating a routine.

New-week draft priorities consider owned assessment weakness evidence and unfinished earlier tasks. Previously approved frequencies, optional/mandatory flags and availability remain available as defaults; the current active plan is not silently rewritten. The editor explains evidence hints and warns when its week extends beyond the profile's target date. Final topic blocks use remaining estimated study time rather than blindly allocating another full-length session.
