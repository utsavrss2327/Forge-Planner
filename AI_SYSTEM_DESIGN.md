# AI and assessment design

Gemini free tier is the user-selected default, using `AI_PROVIDER=gemini`, `AI_MODEL=gemini-3.1-flash-lite`, `GEMINI_API_KEY`. Gemini uses its documented native generateContent endpoint with provider-side JSON Schema, low reasoning effort and a bounded timeout. Groq/OpenAI retain the existing SDK. Groq/OpenAI are explicit alternatives; no automatic paid fallback. Model availability/quotas depend on the provider/account. Gemini's free tier may use submitted content for product improvement; the assessment builder states this before generation. See https://ai.google.dev/gemini-api/docs/pricing and https://ai.google.dev/gemini-api/docs/openai.

Generation (`forge-assessment-v2`) reads the authenticated user's actual video topics/notes, subject-linked journals, completed daily-task descriptions, DSA solution/mistake notes, and due revision. Dates use the saved timezone. Video numbers and titles alone are not treated as a transcript. Context round-robins subjects before bounded truncation; warnings identify excluded/unannotated material. Every question references existing source IDs matching its subject; every represented subject must appear; durations sum to 60 minutes. Model answers and weighted rubrics are saved privately. No fixed sample test is substituted on failure.

Grading (`forge-grading-v2`) freezes persisted answers through the server submission RPC, then grades only those answers. MCQs are exact comparisons and blanks receive zero. Written/code answers are reviewed against each saved criterion, with reason, missing concepts and specific next steps. Application code rejects missing/duplicate questions, duplicate/invalid criteria and marks above bounds, then recomputes totals rather than trusting an AI total. Model failures leave answers submitted and retryable without awarding fabricated marks. AI code review does not execute the submitted program and is labelled accordingly.

Finalization atomically writes per-question feedback, total score, topic evidence/sample counts and next-day revision. Repeated finalization is idempotent. Retests can include due revision sources with fresh questions. Scores describe samples, not a hiring guarantee. No system can guarantee an LLM's factual correctness; users see expected answers, criteria and source links to review disputed results.

Server-only service-role storage is required for private answer keys. The browser never receives it or pre-submission reference answers/rubrics. Quota, timeout, invalid JSON and schema failures are explicit. Provider errors never select a different paid model. Raw prompts/answers are not logged. Current token usage is bounded by request/output caps; a billing/usage dashboard and robust background grading queue are future work.

Roadmap extraction: TXT/MD/CSV/JSON and DOCX/XLSX extraction is local to the server. ZIP directory size/entry limits bound Office extraction; formulas/embedded scripts never execute. PDF/JPG/PNG transcription uses Gemini with explicit review, signatures, file-size limits and no external URL fetching. Users can import several files into extracted text and review the proposed topics before persistence. Audio/video formats are unavailable. Provider-backed extraction has mocked error coverage; live verification requires the Gemini key.

## Live provider calibration

The saved key can list models. Hydrogen timed out on compatibility and native requests, and a Flash3.8 probe timed out. A native Flash-Lite probe succeeded, so the explicit default was set to gemini-3.1-flash-lite rather than silently switching models during requests. Initial full generation was correctly rejected because explanations were omitted; provider-side Zod-derived JSON Schema now requires them. The real fixture verification script exercises the production generation/grading actions with four subject playlists plus DSA, keeps persistence in memory, and never writes fake assessments into the user's account. See supabase/gemini-verification.json and WORK_LOG.md for the final measured outcome; do not infer success from key presence alone.

Final live fixture outcome: Gemini Flash-Lite generated seven validated questions totaling 60 minutes from 17 sample records across four CS subjects plus DSA, and real rubric grading gave an unrelated written answer zero marks. All fixture persistence was in memory; no production progress was changed. The original fully bounded Zod JSON schema exceeded Gemini's serving-state complexity; only structural types, required fields and enums are sent to the provider, while complete numeric/text/array bounds remain enforced after generation. The native generation/grading path is verified; OCR-specific live behavior and a real signed-in production exam remain separate checks.
